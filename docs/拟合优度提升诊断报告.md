## 一、超参数配置审计

### 1.1 已生效的覆盖

5 种物资 × 6 个 model_key 的独立参数配置已全部生效。各模型的 depth/iterations/l2 因物资而异。

### 1.2 发现的遗漏

| 物资 | model_key | 当前状态 | 影响 |
|------|----------|---------|------|
| **电容式电压互感器** | `catboost_direct` | **使用全局默认**: depth=6, iters=1500, l2=3 | 该物资 NZ_CV=0.66（最低），应降为 depth=4+iters=1000 防过拟合 |
| **电容式电压互感器** | `twostage_reg` | **使用全局默认**: depth=6, iters=1500, l2=3 | 该物资是平稳组主力(TwoStage R²=0.325)，参数完全没调 |
| **交流避雷器** | `catboost_direct` | 使用全局默认: depth=6, iters=1500, l2=3 | 虽不直接使用，但有备无患 |

**结论**：电容式电压互感器的超参数实际未被调优——它的 TwoStage R²=0.325 是在默认参数下跑出来的。这是个明显的改进机会。

## 二、瓶颈诊断：拟合效果差的根因逐层分析

### 2.1 瓶颈一（根本性）：因子区分度不足

**现象**：3/4 个外部因子（transformer_bids, monthly_bid_count, uhv_bids）对所有 5 种物资**完全相同**。

```
断路器保护的 transformer_bids 值 = 交流避雷器的 transformer_bids 值
         因为它们是同一个月所有品类共享的"全局月份特征"
```

**根因**：这些因子来自 `build_real_data.py` 的 `load_batch_features()`——按月份聚合**所有**物资的招标公告数，不区分品类。

```python
# 当前代码 (build_real_data.py:83-88)
ws.cell(row=ri, column=4, value=bf.get('transformer_bids', 0))  # 全局！
ws.cell(row=ri, column=5, value=bf.get('monthly_bid_count', 0)) # 全局！
ws.cell(row=ri, column=6, value=bf.get('uhv_bids', 0))           # 全局！
```

**后果**：模型看到的 4 个因子中只有 `项目数量` 在各物资间有区分度——但它又是从同一张 bid_items 表汇总的，属于"同源信息"（用 y 的聚合形式预测 y）。

**模型的实际运作**：
```
13维输入特征 = 8维自回归(lag/rolling/零值指示) + 1维同源(项目数量) + 4维全局
模型学到的模式 ≈ fancy 自回归 + "本月全局招标热度"
```

**验证**：特征重要性中 `lag1` 在直接回归中占 50.2%，在所有特征中独占一半——印证了模型主要靠历史值预测。

### 2.2 瓶颈二（结构性）：Train-Test 分布漂移

测试集（最后12个月，2025-07 到 2026-06）的系统性特征变化：

| 物资 | Train NZ_rate | Test NZ_rate | 漂移方向 | Train max | Test max |
|------|:---:|:---:|------|:---:|:---:|
| 交流避雷器 | 61% | **83%** | ↑ 36% | 6891 | **7580** (超训练集) |
| 电容式电压互感器 | 61% | **83%** | ↑ 36% | 426 | 353 |
| 交流支柱绝缘子 | 61% | **67%** | ↑ 10% | 4888 | 3565 |
| 断路器保护 | 59% | **75%** | ↑ 27% | 173 | 82 |
| 电抗器保护 | 59% | **75%** | ↑ 27% | 67 | 27 |

**5 种物资的测试集非零率全部高于训练集**——测试期的招标活动更密集。这不是随机抽样误差，是国网 2025-2026 年招标批次结构性增加的体现。

因子层面也有结构性变化：

| 因子 | Train μ | Test μ | 变化 |
|------|:---:|:---:|:---:|
| 项目数量（交流避雷器） | 0.68 | 1.00 | **+47%** |
| uhv_bids | 0.48 | 0.92 | **+92%** |

**后果**：模型在训练集上学到的"平均项目数量约 0.68"的模式，在测试集完全不适用。单一 train/test split 让这个问题无法被及时发现。

### 2.3 瓶颈三（方法论）：12个月测试集太短

以断路器保护为例：12 个测试月中 9 个非零，值分布是 [7, 6, 0, 8, 14, 0, **82**, 11, **47**, 12, 1, 0]。其中 82 和 47 两个极端值贡献了 R² 中的大部分方差。如果这两个月在另一组测试月中，R² 可以完全不同。

**单一固定分割的统计可靠性**：12 个数据点上 R² 的 95% 置信区间宽度约为 ±0.3——也就是说当前报告的 R²=0.697 可能是 0.4 或 0.9，取决于运气。

### 2.4 瓶颈四（数据源）：上下游数据问题未解决

| 问题 | 状态 | 对拟合优度的影响 |
|------|------|---------|
| F4: demand_month = 公告月 | **未修复** | 时间序列的 "时间" 本身是错的——模型在错误的时间轴上学习模式 |
| F5: 单位未归一化 | **未修复** | 台+套+千米+吨混在一起 SUM，聚合值是物理上无意义的数字 |
| bid_items → material_demand_total | 依赖 F4+F5 | 训练数据的 Y 轴（需求量）是错误聚合的结果 |

**这是最根本的瓶颈**。在 F4+F5 修复之前，所有"提升拟合优度"的努力都是在错误数据上优化。当前模型是在学习"公告发布时间 + 错误聚合的需求量"的模式——即使 R²=0.9，论文审稿人一旦追问"你的 demand_month 是什么"，论文仍然不可用。

## 三、改进方案（按优先级排列）

### P0：修复上游数据（bidding-ecp-data 项目）

| 修复 | 内容 | 预期提升 |
|------|------|:---:|
| F4 | 用 delivery_first/last 反推月度分配（Excel 列已解析，pipeline.py:detect_column_map 已有对应的列检测） | 使时间轴语义正确 |
| F5 | 按单位分组后独立聚合，至少区分"台/套/只"和"千米/吨"两类 | 使目标变量物理上有意义 |
| 重新生成 data.xlsx | F4+F5 修复后用新 pipeline 生成 | 训练数据从根上正确 |

**这是当前唯一有资格号称"从根上提升 R²"的措施。其他措施都是治标。**

### P1：构建品类特有的外部因子（非全局）

当前 `transformer_bids/monthly_bid_count/uhv_bids` 是所有物资共享的全局变量。改进方向：

```python
# 每种物资独立计算: "包含该物资品类的招标公告数"
# 不是 "所有 transformer 招标的总数"
# 而是 "交流避雷器 这个品类当月出现了几次"
material_specific_bid_count = COUNT WHERE material_name LIKE '%避雷器%'  
```

**可行性**：`bid_items` 表有 material_name 和 notice_id，可以按品类名称关键词匹配，计算每个品类在每个月的出现次数。这是真正的"品类级外部因子"。

### P2：引入季度/月份哑变量作为结构性特征

ECP 的招标节奏有明显的行政日历模式（3/6/9/12 月是高峰期）。当前的特征集中完全没有"月份"这个概念——`month_sin/month_cos` 是对自然季节建模，不对行政季度建模。

```python
# 新增 3 个哑变量（不用 4 个以避免共线性陷阱）
is_q1_end = 1 if month in [3] else 0    # 一季度末
is_q2_end = 1 if month in [6] else 0    # 二季度末
is_q3_end_or_q4_end = 1 if month in [9,12] else 0  # 下半年集中期
```

**为什么有效**：招标公告的发布时间是行政决策的结果，在季度末集中发布。这些哑变量直接编码了数据生成机制。

### P3：滚动窗口评估 + 多窗口平均 R²

将单一 69/12 分割改为 3 个评估窗口：

| 窗口 | 训练集 | 测试集 |
|------|--------|--------|
| W1 | 第1-57月 | 第58-69月 |
| W2 | 第1-63月 | 第64-76月 |
| W3 | 第1-69月 | 第70-81月（当前窗口） |

报告 3 个窗口的平均 R² 和标准差——比单一分割可靠。

### P4：训练集扩充

| 方案 | 可行性 |
|------|--------|
| 使用 SGCC+冀北两个数据源训练（pooled） | 需要两套数据合并到同一格式 |
| 使用更早的数据（2019 年之前） | 需确认 ECP 数据是否覆盖到 2019 年之前 |
| 合成数据增强（非 SarSim0） | 对 R² 的提升不可靠，不建议 |

## 四、电容式电压互感器的特例分析

电容式电压互感器的 `twostage_reg` 超参数完全未被调优——它用的是全局默认值 (depth=6, iters=1500, l2=3)。而该物资 NZ_CV=0.66 是所有物资中最低的，非零值波动最小。从分析报告的结论可知：CV<1 的物资两阶段更优，且越低越不需要强正则化。

**当前**：TwoStage R²=0.325（默认参数）
**优化后预期**：将 depth 降到 4、iterations 降到 800~1000（减少过拟合风险），同时降低 l2 到 2（因为 CV 低，不需要强正则化），预期 R² 提升到 0.35-0.40。

## 六、根本结论

| 限制因素 | 对 R² 影响 | 能否通过调参解决 |
|------|:---:|:---:|
| 3/4 因子是全局的（无物资区分度） | **高** | ❌ 需要重建训练数据 |
| Train-test 分布漂移 | **高** | ❌ 需要滚动窗口评估 |
| 12 月测试集统计可靠性不足 | **中** | ❌ 需要多窗口平均 |
| 个别物资超参数未被调优 | **中低** | ✅ 立即执行 |
| F4+F5 数据源问题 | **致命** | ❌ 需要上游修复 |

**当前在代码层面能做的优化已接近边际收益递减**。下一个实质性的 R² 提升必须从上游数据质量切入。
