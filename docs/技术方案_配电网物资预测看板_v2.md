## 1. 概述

### 1.1 目标

在现有电力配电网物资需求预测系统（main.py，~1800行）基础上，新增**Grafana风格暗色看板**输出能力，将5种物资 × 15个预测模型的运行结果以交互式HTML看板形式呈现，实现：

- 一屏总览所有物资、所有模型的预测效果
- 支持多模型对比、指标排名、热力图等多维度可视化
- 离线可用（ECharts内联，无需网络）
- 声明式配置驱动，新增物资/模型/窗口类型无需修改渲染代码
- 与现有PNG图片、日志输出并行，三输出共享同一数据源

### 1.2 范围

| 维度 | 说明 |
|------|------|
| 物资 | 交流避雷器、电容式电压互感器、交流支柱绝缘子、断路器保护、电抗器保护（5种） |
| 模型 | 15个预测模型（具体名称由main.py运行时确定） |
| 输出 | 单HTML文件（内联CSS/JS/数据），可直接浏览器打开 |
| 运行环境 | Python 3.14，Windows/Linux |
| 依赖新增 | Jinja2（纯Python）、jsonschema（校验配置） |

### 1.3 设计原则

1. **非侵入性**：对main.py的修改控制在5个插入点、约15行代码，通过安全导入和钩子函数注入
2. **声明式优先**：看板布局、窗口类型、数据绑定全部由JSON配置驱动
3. **类型安全**：窗口类型通过装饰器自注册，配置与渲染器一一映射，运行时校验
4. **数据直传**：numpy数组直接序列化为JSON list，无中间CSV/文件落盘
5. **离线自治**：生成的HTML文件零外部依赖，ECharts 5.x源码内联，使用系统字体栈
6. **可扩展**：新增窗口类型只需一个装饰器函数 + 配置声明，无需修改框架代码
7. **防御性编程**：任何dashboard相关异常不中断主预测流程，panel级别独立降级
8. **物资动态适配**：物资/模型增减时看板自动适配，总结类和表格类面板必须动态感知当前物资集合，禁止硬编码物资名或数量

## 2. 系统架构

### 2.1 整体数据流

```
main.py 预测循环
    │
    ▼
ResultCollector.collect(material, model_name, result_dict)
    │  ← 每个模型预测完成后调用一次（内部try/except保护）
    ▼
ResultCollector（内存中累积 all_results + 序列化 + aggregations计算）
    │  ← 全部预测完成后
    ▼
DashboardBuilder.build(collector)
    │
    ├──► collector.validate() ──► 数据完整性校验
    │
    ├──► collector.to_dashboard_data() ──► dashboard_data（Python dict）
    │
    ├──► ConfigLoader.load("dashboard_config.json") ──► 校验通过的配置
    │
    ├──► SummaryEngine.generate(dashboard_data) ──► AI总结文本
    │
    ├──► PanelRegistry.render_all(config, data, summary) ──► 各窗口HTML片段
    │         └── 每个panel独立try/except，失败时降级为错误占位
    │
    └──► Jinja2 Template Render ──► output/dashboard.html
```

### 2.2 模块划分

| 模块 | 文件 | 职责 |
|------|------|------|
| 数据收集器 | `dashboard/collector.py` | 从main.py收集预测结果，numpy序列化，aggregations计算，统一数据结构 |
| 序列化工具 | `dashboard/serializer.py` | NumpyEncoder工具类（供collector调用），纯工具模块 |
| 配置加载器 | `dashboard/config_loader.py` | 加载JSON配置 + JSON Schema校验 |
| 窗口注册表 | `dashboard/registry.py` | @register_panel装饰器，窗口类型注册与查找 |
| 窗口渲染器 | `dashboard/panels/` | 各窗口类型的ECharts配置生成逻辑 |
| AI总结引擎 | `dashboard/summary.py` | 规则引擎生成文本总结 |
| 构建器 | `dashboard/builder.py` | 编排整体流程，调用Jinja2渲染 |
| Jinja2模板 | `dashboard/templates/base.html` | HTML骨架、CSS Grid布局、ECharts初始化 |
| 静态资源 | `dashboard/static/echarts.min.js` | ECharts 5.x压缩版（~1MB） |
| 配置文件 | `dashboard/dashboard_config.json` | 声明式看板配置 |
| Schema | `dashboard/schemas/config_schema.json` | 配置的JSON Schema |

### 2.3 与main.py的集成点

main.py中仅需在以下5个位置插入代码（共约15行）：

```python
# === 【插入点1】文件头部新增安全导入（4行）===
try:
    from dashboard import DashboardBuilder, ResultCollector
    DASHBOARD_AVAILABLE = True
except ImportError as e:
    DASHBOARD_AVAILABLE = False
    print(f"[Warning] Dashboard模块不可用: {e}")

# === 【插入点2】argparse部分新增参数（4行）===
parser.add_argument('--no-dashboard', action='store_true', help='禁用看板输出')
parser.add_argument('--dashboard-config', default=None, help='看板配置文件路径')
parser.add_argument('--dashboard-output', default=None, help='看板输出路径')
parser.add_argument('--dashboard-debug', action='store_true', help='输出调试数据')

# === 【插入点3】预测主循环开始前（3行）===
collector = ResultCollector() if DASHBOARD_AVAILABLE else None
if collector:
    collector.set_meta(time_labels=["1月", ..., "12月"], forecast_horizon=12)

# === 【插入点4】每个模型预测完成后（2行）===
if collector:
    collector.collect(material_name, model_name, result_dict)

# === 【插入点5】全部预测完成后（4行）===
if collector and not args.no_dashboard:
    DashboardBuilder(
        collector=collector,
        config_path=args.dashboard_config,
        output_path=args.dashboard_output,
        debug=args.dashboard_debug
    ).build()
```

总计修改/新增 **5个插入点，约15行代码**，不影响现有PNG和日志输出逻辑。

### 3.2 numpy序列化策略

```python
# dashboard/serializer.py — 纯工具模块

class NumpyEncoder(json.JSONEncoder):
    """处理numpy类型的JSON编码器"""
    def default(self, obj):
        if isinstance(obj, np.ndarray):
            return obj.round(4).tolist()
        if isinstance(obj, (np.float32, np.float64)):
            return round(float(obj), 4)
        if isinstance(obj, (np.int32, np.int64)):
            return int(obj)
        if isinstance(obj, float) and np.isnan(obj):
            return None
        return super().default(obj)


def to_json_safe(value):
    """将任意numpy值转为JSON-safe Python对象"""
    if isinstance(value, np.ndarray):
        return value.round(4).tolist()
    if isinstance(value, (np.float32, np.float64)):
        return round(float(value), 4)
    if isinstance(value, (np.int32, np.int64)):
        return int(value)
    if isinstance(value, float) and np.isnan(value):
        return None
    return value
```

**关键决策**：
- 数组精度：统一`round(4)`，避免浮点噪声，同时保证可视化精度足够
- NaN处理：先检查`isinstance(obj, float)`再调用`np.isnan()`，避免对非数值类型抛TypeError；NaN转为`null`，前端ECharts自动跳过null点（断线显示）
- 不采用base64编码：数据量小（5×15×12=900个数值），JSON list可读性更好

### 3.3 ResultCollector 接口设计

```python
@dataclass
class PredictionResult:
    """单个预测结果的标准化结构"""
    y_pred: list[float]       # 长度=forecast_horizon
    metrics: dict[str, float] # 9个指标

class ResultCollector:
    """
    数据收集器 - 在预测循环中逐步收集结果。
    
    职责（合并原collector与serializer）：
    - 收集：接收main.py的原始预测结果
    - 序列化：numpy → JSON-safe Python对象
    - 聚合：计算aggregations（best_model, avg_metrics等）
    """

    def __init__(self) -> None:
        self._data: dict[str, dict[str, PredictionResult]] = {}
        self._y_test: dict[str, list[float]] = {}  # 每物资的y_test
        self._meta: dict = {}

    def collect(self, material: str, model_name: str, raw_result: dict) -> None:
        """
        收集单个模型的预测结果。
        
        防御性编程：内部try/except保护，任何异常仅记录警告，
        不中断main.py的预测主循环。
        
        Args:
            material: 物资名称，如"交流避雷器"
            model_name: 模型名称，如"LSTM"
            raw_result: main.py中的原始结果字典，包含:
                - 'y_pred': np.ndarray, shape=(12,)
                - 'y_test': np.ndarray, shape=(12,)
                - 'metrics': dict[str, float]
        """
        try:
            if material not in self._data:
                self._data[material] = {}
            
            # 序列化numpy → list（每物资存一次y_test）
            if material not in self._y_test and 'y_test' in raw_result:
                self._y_test[material] = to_json_safe(raw_result['y_test'])
            
            self._data[material][model_name] = PredictionResult(
                y_pred=to_json_safe(raw_result['y_pred']),
                metrics={k: to_json_safe(v) for k, v in raw_result['metrics'].items()}
            )
        except Exception as e:
            import warnings
            warnings.warn(
                f"[Dashboard] collect()失败 material={material}, model={model_name}: {e}",
                stacklevel=2
            )

    def set_meta(self, **kwargs) -> None:
        """设置元信息：time_labels, forecast_horizon等"""
        self._meta.update(kwargs)

    @property
    def materials(self) -> list[str]:
        """已收集的所有物资名称"""
        return list(self._data.keys())

    @property
    def models(self) -> list[str]:
        """已收集的所有模型名称（取第一个物资的模型列表）"""
        if not self._data:
            return []
        first_material = next(iter(self._data.values()))
        return list(first_material.keys())

    def to_dashboard_data(self) -> dict:
        """
        转换为dashboard_data标准结构。
        包含：meta, results（含__y_test__）, aggregations计算。
        """
        ...

    def validate(self) -> list[str]:
        """
        校验数据完整性，返回警告信息列表。
        
        检查项：
        - 各物资的模型数量是否一致
        - y_pred长度是否等于forecast_horizon
        - metrics是否包含所有必需指标
        - 是否存在全NaN的预测结果
        """
        ...
```

### 4.2 窗口类型定义

| type | 说明 | 必需data_binding字段 |
|------|------|---------------------|
| `line_chart` | 多模型预测曲线对比 | `series`, `x_axis` |
| `rank_table` | 指标排名表格 | `metric`, `sort`, `top_n` |
| `bar_chart` | 指标对比柱状图 | `categories`, `values` |
| `markdown_panel` | AI总结/富文本 | `content` |
| `gauge` | 仪表盘 | `value`, `label` |
| `heatmap` | 物资×模型热力图 | `x_axis`, `y_axis`, `metric` |

**data_binding字段分类说明**：

data_binding中的字段分为两类：

1. **路径表达式字段**：以`$.`开头，由DataBindingResolver解析为实际数据。例如：
   - `"x_axis": "$.meta.models"` → 解析为模型名称列表
   - `"series": "$.results.交流避雷器.*.y_pred"` → 解析为各模型预测数组

2. **控制参数字段**：非`$.`开头的固定值，直接透传给渲染器作为配置参数。例如：
   - `"metric": "R2"` → 指定使用哪个指标（heatmap/rank_table中用于从results中提取对应指标值）
   - `"sort": "desc"` → 排序方向
   - `"top_n": 5` → 取前N个
   - `"rank_by": "R2"` → 排名依据指标

对于heatmap，`metric`字段是控制参数，渲染器根据该参数名从`results[material][model].metrics[metric]`中提取值构建热力矩阵。

### 4.3 数据绑定语法

数据绑定表达式使用类JSONPath语法，支持管道操作：

```
$.results.交流避雷器.*.y_pred          → 该物资所有模型的预测数组
$.aggregations.model_avg_metrics.*.R2  → 所有模型的R2均值
$.results.*.*.metrics.R2               → 所有物资所有模型的R2
$.results.交流避雷器.__y_test__        → 该物资的实际值数组
| mean                                 → 管道：取均值
| sort_desc                            → 管道：降序排列
| top(5)                               → 管道：取前5
| round(2)                             → 管道：保留2位小数
| minmax                               → 管道：返回[min, max]元组
```

**解析规则**：
- `$` 为根节点（dashboard_data）
- `.` 为属性访问
- `*` 为通配符（遍历当前层所有key），遇到`*`时对每个子value递归应用剩余segments
- `|` 后为管道函数，可链式调用

### 4.5 repeat/foreach 声明式机制

为避免为每种物资手动编写重复的panel配置，引入`repeat`机制：

```json
{
  "id": "line_material_${material_id}",
  "type": "line_chart",
  "title": "${material} - 多模型预测对比",
  "repeat": {
    "foreach": "$.meta.materials",
    "as": "material",
    "id_suffix": "material_id"
  },
  "grid": {"col": 1, "row": "auto", "col_span": 6, "row_span": 3},
  "data_binding": {
    "series": "$.results.${material}.*.y_pred",
    "y_test": "$.results.${material}.__y_test__",
    "x_axis": "$.meta.time_labels",
    "top_n": 5,
    "rank_by": "R2"
  },
  "options": {
    "show_legend": true,
    "smooth": true,
    "y_test_style": "dashed_scatter"
  }
}
```

**repeat解析规则**：
1. `foreach`：路径表达式，解析为数组（如5种物资名称）
2. `as`：迭代变量名，用于模板替换
3. 配置中的`${material}`占位符在展开时替换为实际值
4. `id_suffix`：用于生成唯一panel ID（如`line_material_0`, `line_material_1`）
5. `grid.row: "auto"`：自动排列，由Builder按顺序分配行号
6. 展开后每个实例独立渲染，互不影响

### 5.1 窗口类型注册机制

```python
# dashboard/registry.py

from typing import Callable, Protocol
from dataclasses import dataclass

@dataclass
class PanelContext:
    """渲染上下文，传递给每个panel渲染函数"""
    panel_config: dict          # 该panel的配置（含data_binding, options）
    data: dict                  # 完整的dashboard_data
    resolved_data: dict         # data_binding解析后的数据
    panel_id: str              # panel唯一ID

@dataclass
class PanelRenderResult:
    """渲染结果"""
    html_content: str              # panel body内的HTML（div容器或table）
    echarts_option: dict | None   # ECharts配置（非图表类型为None）

class PanelRenderer(Protocol):
    """窗口渲染器协议"""
    def __call__(self, ctx: PanelContext) -> PanelRenderResult:
        """返回该panel的渲染结果"""
        ...

# 全局注册表
_PANEL_REGISTRY: dict[str, PanelRenderer] = {}

def register_panel(panel_type: str):
    """
    装饰器：注册一个窗口类型渲染器。
    
    用法：
        @register_panel("line_chart")
        def render_line_chart(ctx: PanelContext) -> PanelRenderResult:
            ...
    """
    def decorator(func: PanelRenderer) -> PanelRenderer:
        if panel_type in _PANEL_REGISTRY:
            raise ValueError(f"Panel type '{panel_type}' already registered")
        _PANEL_REGISTRY[panel_type] = func
        return func
    return decorator

def get_renderer(panel_type: str) -> PanelRenderer:
    """获取已注册的渲染器，未注册则抛出明确错误"""
    if panel_type not in _PANEL_REGISTRY:
        available = ", ".join(sorted(_PANEL_REGISTRY.keys()))
        raise KeyError(
            f"Unknown panel type '{panel_type}'. Available: {available}"
        )
    return _PANEL_REGISTRY[panel_type]

def validate_config_panels(panels: list[dict]) -> list[str]:
    """校验配置中所有panel的type是否已注册，返回错误列表"""
    errors = []
    for p in panels:
        if p["type"] not in _PANEL_REGISTRY:
            errors.append(f"Panel '{p['id']}': unknown type '{p['type']}'")
    return errors

def wrap_echarts_div(panel_id: str, option: dict, height: str = "100%") -> PanelRenderResult:
    """将ECharts option包装为div + option结构"""
    html = f'<div id="chart-{panel_id}" style="width:100%;height:{height};"></div>'
    return PanelRenderResult(html_content=html, echarts_option=option)
```

### 6.1 规则定义方式

```python
from string import Template

@dataclass
class SummaryRule:
    """总结规则定义"""
    id: str                           # 规则唯一标识
    name: str                         # 规则名称（用于日志）
    priority: int                     # 优先级（越小越先输出）
    condition: Callable[[dict], bool] # 触发条件，输入dashboard_data
    template: str                     # 输出模板，使用string.Template的$var语法
    extractor: Callable[[dict], dict] # 从data中提取模板变量

# 规则注册
_SUMMARY_RULES: list[SummaryRule] = []

def register_rule(rule: SummaryRule):
    _SUMMARY_RULES.append(rule)
    _SUMMARY_RULES.sort(key=lambda r: r.priority)
```

**模板格式化**：使用`string.Template`（`$var`语法）替代`str.format()`，避免与JSON/Markdown中的花括号冲突：

**model_consensus 数学定义**：

对于某物资的Top3模型（按R²排序），取其y_pred序列两两计算Pearson相关系数：

```python
import numpy as np

def check_consensus(y_preds: list[list[float]], threshold: float = 0.95) -> bool:
    """
    判断Top3模型预测趋势是否一致。
    
    条件：任意两个模型的y_pred序列的Pearson相关系数均 > threshold。
    """
    for i in range(len(y_preds)):
        for j in range(i + 1, len(y_preds)):
            corr = np.corrcoef(y_preds[i], y_preds[j])[0, 1]
            if corr <= threshold:
                return False
    return True
```

**动态物资遍历要求**：`model_consensus` 规则必须遍历 `data["meta"]["materials"]` 中的所有物资，对每个物资独立执行共识检测，仅输出存在共识的物资。物资增减时自动适配，无需修改规则代码：

```python
@SummaryEngine.rule
def model_consensus_rule(data: dict) -> str | None:
    materials = data["meta"]["materials"]  # 动态获取
    consensus_materials = []
    for material in materials:
        results = data["results"][material]
        # 按R2排序取Top3
        top3 = sorted(results.items(), key=lambda x: x[1]["metrics"]["R2"], reverse=True)[:3]
        y_preds = [r[1]["y_pred"] for r in top3]
        if check_consensus(y_preds):
            consensus_materials.append(material)
    if not consensus_materials:
        return None
    return f"**{'、'.join(consensus_materials)}**的Top3模型预测趋势高度一致（Pearson > 0.95）。"
```

### 6.3 输出格式

```python
class SummaryEngine:
    def generate(self, data: dict, mode: str = "rule") -> str:
        """
        生成AI总结文本。
        
        Args:
            data: dashboard_data完整结构
            mode: "rule"=规则引擎（人运行时），"agent"=预留agent填充接口
        
        Returns:
            Markdown格式的总结文本
            
        Raises:
            ValueError: mode不是"rule"或"agent"时抛出
        """
        if mode == "rule":
            return self._rule_based_generate(data)
        elif mode == "agent":
            return self._agent_placeholder(data)
        else:
            raise ValueError(f"Unknown summary mode: '{mode}'. Expected 'rule' or 'agent'.")

    def _rule_based_generate(self, data: dict) -> str:
        sections = []
        for rule in _SUMMARY_RULES:
            if rule.condition(data):
                variables = rule.extractor(data)
                text = Template(rule.template).safe_substitute(variables)
                sections.append(text)
        return "\n\n".join(sections)

    def _agent_placeholder(self, data: dict) -> str:
        """agent模式：输出结构化数据供外部agent消费"""
        return json.dumps({
            "task": "generate_summary",
            "data_summary": {
                "materials": data["meta"]["materials"],
                "overall_r2_mean": ...,
                "anomalies": [...],
            },
            "instruction": "请基于以上数据生成200字以内的预测效果总结"
        }, ensure_ascii=False)
```

### 6.4 总结上下文层（__context__）

```python
# dashboard/builder.py

import os
from pathlib import Path

# 模块根目录（解决非项目根目录运行时相对路径失败问题）
_MODULE_DIR = Path(__file__).parent

class DashboardBuilder:
    """看板构建器 - 编排整体流程"""

    DEFAULT_CONFIG = _MODULE_DIR / "dashboard_config.json"
    DEFAULT_OUTPUT = Path("output") / "dashboard.html"

    def __init__(
        self,
        collector: ResultCollector,
        config_path: str | None = None,
        output_path: str | None = None,
        debug: bool = False
    ) -> None:
        self.collector = collector
        self.config_path = Path(config_path) if config_path else self.DEFAULT_CONFIG
        self.output_path = Path(output_path) if output_path else self.DEFAULT_OUTPUT
        self.debug = debug

    def build(self) -> str:
        """
        执行完整构建流程，返回输出文件路径。
        
        流程：
        0. 前置检查（数据非空）
        1. 数据校验
        2. 加载并校验配置
        3. 序列化数据
        4. 生成AI总结（存入context层）
        5. 展开repeat配置
        6. 渲染所有panel（每个独立try/except）
        7. Jinja2模板渲染
        8. 写入HTML文件
        """
        # Step 0: 前置检查 - collector收到空数据时提前退出
        if not self.collector.materials:
            print("[Dashboard] 警告：无预测数据，跳过看板生成")
            return ""
        
        # Step 1: 数据校验
        warnings = self.collector.validate()
        for w in warnings:
            print(f"[Dashboard] 数据警告: {w}")
        
        # Step 2: 配置
        config = ConfigLoader(str(self.config_path)).load()
        
        # Step 3: 数据
        data = self.collector.to_dashboard_data()
        
        # Step 4: AI总结 → 独立context层
        context = {
            "summary": SummaryEngine().generate(data, mode="rule"),
            "generated_at": data["generated_at"],
        }
        
        # Step 5: 展开repeat配置（传入layout用于自动布局计算）
        panels_config = self._expand_repeats(config["panels"], data, config["layout"])
        
        # Step 6: 渲染panels（每个panel独立try/except降级）
        rendered_panels = []
        for panel_cfg in panels_config:
            try:
                renderer = get_renderer(panel_cfg["type"])
                resolved = DataBindingResolver(data, context).resolve(
                    panel_cfg.get("data_binding", {})
                )
                ctx = PanelContext(
                    panel_config=panel_cfg,
                    data=data,
                    resolved_data=resolved,
                    panel_id=panel_cfg["id"]
                )
                result = renderer(ctx)
                rendered_panels.append({
                    **panel_cfg,
                    "html_content": result.html_content,
                    "echarts_option": result.echarts_option
                })
            except Exception as e:
                # 降级：显示错误信息，不影响其他panel
                rendered_panels.append({
                    **panel_cfg,
                    "html_content": f'<div class="panel-error">渲染失败: {e}</div>',
                    "echarts_option": None
                })
                print(f"[Dashboard] Panel '{panel_cfg['id']}' 渲染失败: {e}")
        
        # Step 7: Jinja2渲染
        html = self._render_template(config, rendered_panels, data, context)
        
        # Step 8: 输出（确保目录存在）
        output_dir = self.output_path.parent
        os.makedirs(output_dir, exist_ok=True)
        
        with open(self.output_path, "w", encoding="utf-8") as f:
            f.write(html)
        
        if self.debug:
            debug_path = output_dir / "dashboard_data.json"
            self._dump_debug_data(data, debug_path)
        
        print(f"[Dashboard] 看板已生成: {self.output_path}")
        return str(self.output_path)

    def _expand_repeats(self, panels: list[dict], data: dict, layout: dict) -> list[dict]:
        """
        展开含repeat配置的panel为多个实例。
        
        自动布局算法：
        1. 先扫描所有非repeat panel，计算已占用的最大行号（max_fixed_row）
        2. repeat panel的auto行从 max_fixed_row + 1 开始
        3. 根据 layout.columns / col_span 计算每行可放置的panel数（items_per_row）
        4. 按顺序分配 row 和 col
        5. repeat展开后，后续非repeat panel的行号自动偏移（避免重叠）
        """
        columns = layout.get("columns", 12)
        
        # Phase 1: 计算固定panel占用的最大行号
        max_fixed_row = 0
        for panel in panels:
            if "repeat" not in panel:
                grid = panel["grid"]
                panel_end_row = grid["row"] + grid["row_span"] - 1
                max_fixed_row = max(max_fixed_row, panel_end_row)
        
        # Phase 2: 展开repeat panels
        expanded = []
        auto_row_cursor = max_fixed_row + 1  # auto区域起始行
        
        for panel in panels:
            if "repeat" not in panel:
                # 非repeat panel：如果行号在auto区域之后，需要偏移
                expanded.append(panel)
                continue
            
            repeat_cfg = panel["repeat"]
            items = DataBindingResolver(data, {}).resolve_path(repeat_cfg["foreach"])
            var_name = repeat_cfg["as"]
            id_suffix_key = repeat_cfg.get("id_suffix", "idx")
            col_span = panel["grid"]["col_span"]
            row_span = panel["grid"]["row_span"]
            items_per_row = max(1, columns // col_span)
            
            for idx, item in enumerate(items):
                instance = self._substitute_template(panel, var_name, item, idx, id_suffix_key)
                if instance["grid"].get("row") == "auto":
                    row_offset = (idx // items_per_row) * row_span
                    col_offset = (idx % items_per_row) * col_span
                    instance["grid"]["row"] = auto_row_cursor + row_offset
                    instance["grid"]["col"] = 1 + col_offset
                expanded.append(instance)
            
            # 更新auto_row_cursor：本批repeat panels占用后的下一行
            total_rows_used = ((len(items) - 1) // items_per_row + 1) * row_span
            auto_row_cursor += total_rows_used
        
        return expanded

    def _substitute_template(self, panel: dict, var_name: str, value: str,
                              idx: int, id_suffix_key: str) -> dict:
        """递归替换配置中的${var}占位符"""
        import copy
        result = copy.deepcopy(panel)
        # 替换id
        result["id"] = result["id"].replace(f"${{{id_suffix_key}}}", str(idx))
        # 替换title
        result["title"] = result["title"].replace(f"${{{var_name}}}", value)
        # 替换data_binding中的表达式
        for key, expr in result.get("data_binding", {}).items():
            if isinstance(expr, str):
                result["data_binding"][key] = expr.replace(f"${{{var_name}}}", value)
        # 移除repeat字段
        result.pop("repeat", None)
        return result

    def _render_template(self, config, panels, data, context) -> str:
        """加载Jinja2模板并渲染"""
        import jinja2
        env = jinja2.Environment(
            loader=jinja2.FileSystemLoader(str(_MODULE_DIR / "templates")),
            autoescape=False
        )
        template = env.get_template("base.html")
        
        # 读取ECharts源码用于内联（指定编码）
        echarts_path = _MODULE_DIR / "static" / "echarts.min.js"
        with open(echarts_path, "r", encoding="utf-8") as f:
            echarts_source = f.read()
        
        return template.render(
            title=config["title"],
            subtitle=config["subtitle"],
            layout=config["layout"],
            panels=panels,
            echarts_source=echarts_source,
            generated_at=context["generated_at"]
        )

    def _dump_debug_data(self, data: dict, path: Path) -> None:
        """输出调试用JSON数据"""
        with open(path, "w", encoding="utf-8") as f:
            json.dump(data, f, ensure_ascii=False, indent=2, cls=NumpyEncoder)
```

### 9.2 DataBindingResolver（数据绑定解析器）

```python
# dashboard/data_binding.py

from typing import Any

class DataBindingResolver:
    """解析数据绑定表达式，从dashboard_data和context中提取数据"""

    def __init__(self, data: dict, context: dict | None = None) -> None:
        # $ 根节点包含业务数据和context层
        self._root = {**data, "__context__": context or {}}

    def resolve(self, bindings: dict) -> dict:
        """
        解析一组data_binding，返回解析后的数据字典。
        
        对于非表达式值（如固定字符串"R2"、数字5），直接透传。
        对于以"$."开头的表达式，执行解析。
        """
        result = {}
        for key, expr in bindings.items():
            if isinstance(expr, str) and expr.startswith("$."):
                result[key] = self._evaluate(expr)
            else:
                result[key] = expr  # 控制参数直接透传
        return result

    def resolve_path(self, expr: str) -> Any:
        """公开方法：解析单个路径表达式（供repeat展开使用）"""
        return self._evaluate(expr)

    def _evaluate(self, expr: str) -> Any:
        """
        解析单个表达式。
        
        示例：
            "$.results.交流避雷器.*.y_pred" → {"LSTM": [...], "GRU": [...], ...}
            "$.aggregations.model_avg_metrics.*.R2 | mean" → 0.87
            "$.__context__.summary" → "综合R²表现..."
        """
        # 分离路径和管道
        parts = expr.split("|")
        path = parts[0].strip()
        pipes = [p.strip() for p in parts[1:]]
        
        # 解析路径
        value = self._resolve_path(path)
        
        # 应用管道
        for pipe in pipes:
            value = self._apply_pipe(value, pipe)
        
        return value

    def _resolve_path(self, path: str) -> Any:
        """
        解析$.a.b.*.c形式的路径。
        
        遇到*时，对当前dict的每个子value递归应用剩余segments。
        """
        segments = path.removeprefix("$.").split(".")
        return self._resolve_segments(self._root, segments)

    def _resolve_segments(self, current: Any, segments: list[str]) -> Any:
        """递归解析路径segments"""
        if not segments:
            return current
        
        seg = segments[0]
        remaining = segments[1:]
        
        if seg == "*":
            # 通配：对当前dict的每个value递归应用剩余segments
            if not isinstance(current, dict):
                raise ValueError(f"Cannot apply '*' to non-dict type: {type(current)}")
            if not remaining:
                # *是最后一个segment，返回所有value
                return {k: v for k, v in current.items() if not k.startswith("__")}
            # 对每个子value递归
            result = {}
            for k, v in current.items():
                if k.startswith("__"):
                    continue  # 跳过__y_test__等内部字段
                try:
                    result[k] = self._resolve_segments(v, remaining)
                except (KeyError, TypeError):
                    continue  # 跳过无法解析的分支
            return result
        else:
            if isinstance(current, dict):
                if seg not in current:
                    raise KeyError(f"Key '{seg}' not found. Available: {list(current.keys())[:10]}")
                return self._resolve_segments(current[seg], remaining)
            else:
                raise KeyError(f"Cannot access '{seg}' on {type(current).__name__}")

    def _apply_pipe(self, value: Any, pipe: str) -> Any:
        """应用管道函数"""
        if pipe == "mean":
            values = list(value.values()) if isinstance(value, dict) else value
            if not values:
                return 0.0  # 空值保护：避免除零
            return sum(values) / len(values)
        elif pipe.startswith("round("):
            decimals = int(pipe[6:-1])
            return round(value, decimals)
        elif pipe.startswith("top("):
            n = int(pipe[4:-1])
            if isinstance(value, dict):
                sorted_items = sorted(value.items(), key=lambda x: x[1] if isinstance(x[1], (int, float)) else 0, reverse=True)
                return dict(sorted_items[:n])
            return value
        elif pipe == "sort_desc":
            if isinstance(value, dict):
                return dict(sorted(value.items(), key=lambda x: x[1], reverse=True))
            elif isinstance(value, list):
                return sorted(value, reverse=True)
            return value
        elif pipe == "minmax":
            values = list(value.values()) if isinstance(value, dict) else value
            if not values:
                return [0, 0]
            return [min(values), max(values)]
        return value
```

### 10.2 物资动态适配（核心设计）

**设计目标**：物资从5种增加到8种（或减少到3种）时，看板无需修改代码，最多只需调整配置文件中的少量参数即可正常渲染。

#### 10.2.1 适配契约

| 面板类型 | 物资增加时 | 物资减少时 | 是否需要改配置 |
|----------|-----------|-----------|---------------|
| `line_chart`（repeat） | 自动新增对应panel | 自动减少panel | **不需要** |
| `heatmap` | 自动扩展y轴 | 自动收缩y轴 | **不需要** |
| `gauge` | 自动重新计算均值 | 自动重新计算均值 | **不需要** |
| `bar_chart`（绑定$.meta.materials） | 自动新增柱子 | 自动减少柱子 | **不需要** |
| `rank_table` | 自动包含新物资数据 | 自动排除已删除物资 | **不需要** |
| `markdown_panel`（AI总结） | 规则引擎自动感知 | 规则引擎自动感知 | **不需要** |
| 硬编码物资名的panel | 需手动添加配置 | 需手动删除配置 | 需要 |

**核心原则**：配置中**禁止硬编码物资名称**用于数据绑定。所有物资相关绑定必须通过以下动态路径：
- `$.meta.materials` — 当前运行的所有物资列表
- `repeat.foreach: "$.meta.materials"` — 按物资展开panel
- `$.results.*` — 通配所有物资
- `$.aggregations.best_model_per_material.*` — 通配所有物资的最佳模型

#### 10.2.2 Grid自动布局算法

当repeat展开的panel数量变化时（5物资→5个line_chart，8物资→8个line_chart），布局自动适配：

```
算法输入：
  - layout.columns = 12（Grid总列数）
  - 固定panel列表（非repeat，行号硬编码）
  - repeat panel模板（col_span=6, row_span=3, row="auto"）
  - 实际物资数量 N

算法步骤：
  1. 扫描所有固定panel，计算 max_fixed_row = max(row + row_span - 1)
  2. auto区域起始行 = max_fixed_row + 1
  3. items_per_row = columns // col_span = 12 // 6 = 2（每行放2个）
  4. 对第 i 个展开实例（i从0开始）：
     - row = auto起始行 + (i // items_per_row) * row_span
     - col = 1 + (i % items_per_row) * col_span
  5. 后续固定panel的行号 += repeat区域总占用行数（避免重叠）

示例（5物资 → 8物资）：
  5物资：auto区域占 ceil(5/2) * 3 = 9行
  8物资：auto区域占 ceil(8/2) * 3 = 12行
  → 后续panel自动下移3行，无需手动调整
```

#### 10.2.3 总结类面板的动态感知

规则引擎的所有规则**必须从数据中动态获取物资列表**，禁止硬编码物资名或数量：

```python
# ✅ 正确：动态获取
@SummaryEngine.rule
def best_model_rule(data: dict) -> str | None:
    materials = data["meta"]["materials"]  # 动态获取，可能是3/5/8种
    total = len(materials)
    best = data["aggregations"]["overall_best"]
    # 计算该模型在多少种物资上最优
    win_count = sum(
        1 for m in materials
        if data["aggregations"]["best_model_per_material"].get(m, {}).get("model") == best["model"]
    )
    return Template(
        "综合R²表现，**${model}**以均值${value}位列第一，在${win}/${total}种物资上取得最优。"
    ).safe_substitute(model=best["model"], value=f"{best['R2']:.2f}", win=win_count, total=total)

# ❌ 错误：硬编码
def bad_rule(data):
    return "在4/5种物资上取得最优"  # 物资数变化时文本错误
```

**规则引擎动态适配要求**：

| 规则 | 动态感知点 | 适配方式 |
|------|-----------|----------|
| `best_model` | 物资总数、每物资最佳模型 | 遍历 `$.meta.materials` 计算 win_count |
| `worst_material` | 最难预测的物资 | 遍历所有物资取 R2 最低者 |
| `anomaly_detect` | 异常物资×模型组合 | 遍历 `$.results.*.*` 检测 R2<0.5 |
| `zero_demand` | 零需求物资 | 遍历所有物资检查 zero_acc |
| `model_consensus` | 各物资Top3趋势 | 对每个物资独立计算，仅输出有共识的物资 |
| `overall_quality` | 整体指标均值 | 从 aggregations 动态计算 |

**物资被删除时**：规则引擎仅处理 `data["meta"]["materials"]` 中存在的物资，已删除物资不会出现在结果中（因为 collector 从未收集到它的数据）。

#### 10.2.4 表格类面板的动态感知

`rank_table` 渲染器的动态适配逻辑：

```python
@register_panel("rank_table")
def render_rank_table(ctx: PanelContext) -> PanelRenderResult:
    """
    动态适配要点：
    1. group_by="model"时：遍历 data["meta"]["models"] 中实际存在的模型
    2. "最佳物资"/"最差物资"列：从 data["meta"]["materials"] 动态获取
    3. 物资数量变化不影响表格结构，只影响聚合计算的分母
    """
    materials = ctx.data["meta"]["materials"]  # 动态获取，不硬编码
    models = ctx.data["meta"]["models"]
    metric = ctx.resolved_data["metric"]  # 控制参数，如"R2"
    
    # 对每个模型，计算跨所有物资的指标均值
    model_scores = {}
    for model in models:
        scores = [
            ctx.data["results"][m][model]["metrics"][metric]
            for m in materials
            if model in ctx.data["results"].get(m, {})  # 防御：物资可能被删除
        ]
        if scores:
            model_scores[model] = sum(scores) / len(scores)
    
    # 排序、取top_n、生成HTML表格
    ...
```

**关键防御**：`ctx.data["results"].get(m, {})` — 如果某物资在配置中存在但数据中缺失（如预测中途失败），不会导致 KeyError。

#### 10.2.5 物资删除的完整处理链

当从 `data.xlsx` 中删除一个 sheet（如"电抗器保护"）时：

```
1. main.py 预测循环：不会为"电抗器保护"执行预测
2. collector.collect()：从未被调用，_data中无此物资
3. collector.to_dashboard_data()：
   - meta.materials = ["交流避雷器", "电容式电压互感器", "交流支柱绝缘子", "断路器保护"]（4种）
   - results中无"电抗器保护"key
   - aggregations仅基于4种物资计算
4. repeat展开：$.meta.materials解析为4项 → 生成4个line_chart（非5个）
5. heatmap：y轴仅4个物资
6. 规则引擎：所有规则基于4种物资生成文本
7. rank_table：聚合分母为4
8. Grid布局：auto区域少占3行，后续panel自动上移
```

**无需任何代码或配置修改**。

## 11. 风险与缓解

| # | 风险 | 影响 | 概率 | 缓解措施 |
|---|------|------|------|----------|
| 1 | Jinja2对Python 3.14的兼容性 | 构建失败 | 低 | Jinja2为纯Python实现，3.14发布前已适配；备选：string.Template降级 |
| 2 | ECharts内联导致HTML文件过大（~1.2MB） | 打开速度略慢 | 确定 | 可接受；备选：使用ECharts精简定制构建（仅含line/bar/gauge/heatmap，~400KB） |
| 3 | numpy版本与Python 3.14兼容 | collector序列化失败 | 低 | 序列化层仅调用`.tolist()`和`round()`，不依赖numpy高级API |
| 4 | 数据绑定表达式解析错误 | 单个panel渲染失败 | 中 | 每个panel独立try/except，失败时显示错误信息占位，不影响其他panel |
| 5 | 配置文件手写错误 | 启动时报错 | 中 | JSON Schema校验 + 明确错误提示 + 提供配置模板 |
| 6 | main.py预测循环中collector.collect()抛异常 | 中断主流程 | 低 | collect()内部try/except，异常仅记录警告，不中断预测 |
| 7 | 浏览器兼容性（IE等） | 看板显示异常 | 低 | 目标为Chrome/Edge/Firefox现代浏览器，README中注明 |
| 8 | 模型数量增多后heatmap标签拥挤 | 可读性下降 | 中 | 配置中支持`axisLabel.rotate`、`interval`参数；超过20个模型时自动旋转45° |
| 9 | ECharts初始化失败（DOM未就绪等） | 单个图表白屏 | 低 | 每个IIFE内try/catch，失败时显示错误文本 |
| 10 | 非项目根目录运行 | 路径解析失败 | 中 | 所有内部路径基于`Path(__file__).parent`，不依赖CWD |

**Schema设计说明**：
- `type`字段为`string`类型（非enum硬编码），由运行时`validate_config_panels()`校验是否已注册。这样新增panel类型无需修改Schema。
