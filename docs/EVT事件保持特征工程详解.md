# EVT 事件保持特征工程——从原理到实践

## 一、先理解问题：为什么"抄作业"是错的

### 1.1 一个生活中的例子

你是一家公司的老板，想知道下个月公司会发多少工资。你翻看了过去三年的工资记录：

```
1月: 50万    4月: 50万    7月: 48万    10月: 55万
2月: 0       5月: 0       8月: 0       11月: 0
3月: 52万    6月: 52万    9月: 50万    12月: 53万
```

现在我问你：2026 年 7 月的工资是多少？

你会怎么做？

**做法 A（抄去年的作业）**：2025 年 7 月发了 48 万，所以预测 48 万。这是`lag12`（同比滞后）的逻辑。

**做法 B（看最近几个月趋势）**：4 月发了 50 万，5 月发了 0，6 月发了 52 万，平均约 34 万，所以预测 34 万。这是`rolling3`（滚动均值）的逻辑。

**做法 C（看事件模式）**："过去 12 个月中有 6 个月发了工资（每月一次）。最近一次是 6 月（发了 52 万）。7 月从来不发工资（过去 3 年 7 月都是 0）"，所以预测 0。

### 1.2 做法 C 为什么比 A 和 B 更聪明

| 做法 | 逻辑 | 预测 7 月 | 实际 7 月 | 对不？ |
|------|------|:---:|:---:|:---:|
| A (抄去年) | 去年 7 月=48 万 | 48 万 | 0 | ❌ |
| B (看最近) | 最近 3 月平均 34 万 | 34 万 | 0 | ❌ |
| C (看事件) | 7 月从不发工资 | 0 | 0 | ✅ |

A 和 B 的共同问题：它们把工资发放当成"连续流"——假设上个月发多少、上上个月发多少，这个月大概也差不多。**但工资发放是离散事件——每个月要么发（发薪月），要么不发（非发薪月）。**

ECP 的物资采购数据和工资发放完全一样：
- 3 月国网发了一个招标公告 → 交流避雷器有 500 台的**需求事件**
- 4 月没发公告 → 需求量是 0（事件不发生）
- 6 月发了公告 → 需求量 750 台（事件发生）

## 二、传统特征的"翻译错误"

机器学习的特征一般围绕"连续信号"设计：距离、密度、均值、加权和。这些特征在连续时域有直观的物理意义，但在"事件/空白"的离散二进位世界里常被扭曲。

### 2.1 lag1（上个月的值）在说什么？

```
真实世界：3 月有采购事件(500 台) → 4 月没有采购事件(0)
lag1 视角：3 月=500 → 预测 4 月=500 → 错了
          ——它把事件量值直接投射到下一个时间步，混淆了"量大"和"一定会延续"
```

### 2.2 rolling3（近 3 月均值）在说什么？

```
4 月的 rolling3 = (3月500 + 2月0 + 1月200) / 3 ≈ 233
5 月的 rolling3 = (4月0 + 3月500 + 2月0) / 3 ≈ 167
6 月的 rolling3 = (5月0 + 4月0 + 3月500) / 3 ≈ 167
```

这三个数字在描述同一次事件（3 月有 500 的需求），只是随着窗口滑动在衰减。**一次事件被反复分散到三个月中，生成了一条假的连续趋势。**

### 2.3 sin/cos 编码在说什么？

```
sin(2π×3/12) = 1.0  —— 3 月
sin(2π×9/12) = -1.0 —— 9 月
```

它们描述的是自然季节，不是行政日历。国网招标高峰在 3/6/9/12 月，是人为规划的决策节奏，和四季更替无关。

## 三、EVT 的中心思想：描述事件，而非描述数值

EVT（Event-preserving feature engineering）的核心主张：

> 如果数据由"事件发生 / 事件不发生"两个状态交替构成，那就应该用**事件结构特征**来建模——特征描述的不是"上个月的数值是什么"，而是"上一次事件发生在什么时候、事件密度多高、这个月历史上是事件月吗"。

### 3.1 一个类比

你去咖啡店买咖啡。有时候买一杯（事件：买咖啡，量值：1杯），有时候不买（事件不发生）。如果要预测你今天是否会买咖啡，下列哪条最有用？

A. "昨天买了 1 杯"——连续思维，没啥用，你又不总是每天买

B. "过去 7 天你只买了 2 次"——这是**事件密度**。你今天仍然可能不买——因为你的平均频率就是 2 次/周

C. "已经连续 3 天没买了"——这是**事件间隔**。间隔越长，你今天越可能买（因为"忍太久了"）

D. "周五你几乎从不买咖啡，概率只有 10%"——这是**历史事件频率**。今天周五，所以你今天买咖啡不太可能

B、C、D 都是事件结构特征。它们不问"昨天买了多少杯"，而问"最近事件多不多、上次事件有多远了、这个时段的事件概率是多少"。

## 四、EVT 的五类特征

SHOS（Stop-Hoover-Occurrence-Sequence）-based EVT 构建了四个类别的事件结构特征。在我们的项目中使用了前五类：

### 4.1 Stop 类——"距上次事件过了多久"

**编码含义**：上一次发生需求事件的月份距离现在有多远。

```
计算方式：对每个月，扫描到最近一次正需求的月数。

例：交流避雷器
  3月(500台→事件!) resets counter to 0
  4月(0台)     counter=1  (1个月没发生)
  5月(0台)     counter=2  (2个月没发生)
  6月(750台→事件!) resets counter to 0
```

**为什么有用**：ECP 的季度批次招标有间隔——通常在 3/6/9/12 月发布。`gap_since_last` 编码了"我们在这个事件周期中的位置"：

- 间隔=0~2 个月 → 上季度刚发过标，短期内不太可能再发
- 间隔=3~4 个月 → 邻近新季度的标期，大概率有新标

### 4.2 Hoover 类——"事件密度"

**编码含义**：在滑动窗口内（过去 6 个月 / 过去 12 个月），正需求出现了几次。

```
本项目中：
  evt_cnt_6m(t)  = 过去 6 个月(含本月)中有需求的月数
  evt_cnt_12m(t) = 过去 12 个月(含本月)中有需求的月数
  cumul_12m(t)   = 过去 12 个月(含本月)的需求总量
```

**为什么有用**：这比 `rolling3` 更直接地回答了"这个物资的采购频率"：

- `rolling3` = (500+0+0)/3 = 167 → "平均约 167 台/月"（数值平均值，被零稀释）
- `evt_cnt_6m` = 2/6 → "半年内采购了 2 次"（事件次数，不受零稀释）

`evt_cnt_12m=5` 明确告诉模型"今年这个品类采购了 5 次（典型的一年 4~6 次的批次节奏）"，这是 `lag12` 和 `rolling3` 无法直接表达的。

### 4.3 Occurrence 类——"历史事件频率"

**编码含义**：在过去所有数据中，这个月（例如 3 月）出现正需求的频率。

```
month_freq = 训练集中所有3月份中，有需求的比例

例：2020年3月=有需求，2021年3月=有需求，2022年3月=有需求，2023年3月=有需求，2024年3月=有需求
  → month_freq(3月) = 5/5 = 1.0  "3月永远有采购"
  
  2020年5月=有需求，2021年5月=无需求，2022年5月=无需求，2023年5月=无需求，2024年5月=有需求
  → month_freq(5月) = 2/5 = 0.4  "5月有时有采购，不保证"
```

**为什么有用**：这是行政日历最直接的编码——不需要外部知识（如"国网在季度末发标"），纯从数据中自动发现"某几个月的采购概率高于其他月"。和 sin/cos 的区别在于——sin/cos 假设周期是平滑的正弦波，`month_freq` 允许周期出现任意形状（比如 3 月和 9 月概率极高，而其他月极低——这在 sin/cos 中是做不到的）。

### 4.4 不被使用的 Sequence 类及原因

`last_evt_mag`、`evt_trend`、`evt_cv` 是 Sevquence 特征——描述事件量值的趋势。它们在训练时逐月变化，但在做预测时**退化为常数值**（因为无法知道测试期是否有新事件发生），所以从最终特征集中移除了。

## 五、EVT 在训练和预测中的工作流程

### 5.1 训练阶段

```
训练数据: 2020年5月 ~ 2024年6月 (69个月)

对这个69个月的训练序列, 逐月计算 5 个事件特征:

月份     | demand | gap_since_last | evt_cnt_6m | evt_cnt_12m | cumul_12m | month_freq
2020-05  |  200   |       7        |     1      |      1      |    200    |   0.33
2020-06  |  500   |       0        |     2      |      2      |    700    |   0.67
2020-07  |    0   |       1        |     2      |      2      |    700    |   0.25
...

→ 所有特征值都是基于"当时已知的信息"计算的 (没有未来信息)
→ CatBoost 学习: demand_pred = f(外部因子, lag特征, EVT特征)
```

### 5.2 预测阶段

```
训练数据: 2020年5月 ~ 2025年6月 (69个月, 做了新预测时使用全部69个月)
测试数据: 2025年7月 ~ 2026年6月 (12个月, 我们要预测的12个未来月)

对于 2025年7月 (要预测的第1个月):
  gap_since_last = 从训练集最后一个事件(假设是2025年6月)开始算 = 1 个月
  evt_cnt_6m    = 从 2025年2月~2025年7月 的预期事件数
                  因为2025年7月我们还没看到真实值, 用过去的数据来算
                  实际已经用到2025年6月前的数据 + 预测值来延续
  month_freq    = "7 月在训练集中出现需求的频率"
  等等
```

**关键**：EVT 在训练时逐月变化（真实值）；在预测时用训练集最后已知值 + 已预测的值滚动计算。

## 六、为什么 EVT 能提升拟合优度

### 6.1 信息增益的直观解释

当前最佳模型（CatBoost-2S）的特征工程主要围绕"连续信号"设计：

```
lag1:  上个月需求量 → 隐含假设: 本期和上月连续相关
lag12: 去年同期需求量 → 隐含假设: 季节性模式平稳重复
roll3: 滚动均值 → 隐含假设: 近期趋势线延伸
```

而 EVT 提供了**不同结构的信息源**：

```
gap_since_last: 我们在当前事件周期中的位置
evt_cnt_6m:     我们最近有多"忙"
evt_cnt_12m:    我们的年度采购节律
cumul_12m:      年度累计需求的客观尺度
month_freq:     是否是"传统采购月"
```

训练集中 69 个月包含约 40 次"事件月"和 30 次"空白月"。纯 lag 特征在这些月份中的区分度是有限的——一次事件的影响随 lag1、lag3 的衰减快速扩散。而 EVT 的"事件密度"和"月度频率"在传统特征失效的区间仍然提供区分度：比如"lag1 和 lag12 都是 0（无信号）但 month_freq=0.8（本月大概率有采购）"→ 模型由此获得正确的预测方向。

### 6.2 为什么不是所有物资都受益

EVT 对"事件规律且低频"的物资效果最大。

| 特征 | 交流避雷器（受损） | 电容式电压互感器（大受益） |
|------|---------|---------|
| 需求模式 | **暴降模式**：0 月越长 → 下一次爆发越大 | **稳定事件规律**：3/6/9/12 月各一次 |
| month_freq 在 3 月 | 高（3 月几乎总是爆发） | 高（3 月恒有采购，量不极端） |
| evt_cnt_6m 在暴增前 | 极低（连续 5 个月为 0） | 中低 |
| 模型学到 | "0 事件 = 低需求" | "0 事件 = 下一个事件月可能要来了" |
| 实际是 | "0 事件 → 积压大单将暴增" | "0 事件 → 等待下个季度" |

交流避雷器的大单爆发模式使得 Hoover 类特征学到的方向反了——"连续 0 月后必有大单"这一模式需要通过极端的 `cumul_12m` 才能表达，而纯事件计数 `evt_cnt` 对这种情况会产生误导。

## 七、我们在本项目中的具体用法

### 7.1 特征集

| 特征名 | 类型 | 计算方式 | 维度 |
|--------|------|---------|:---:|
| `gap_since_last` | Stop | 距上次正需求的月数 | 1 |
| `evt_cnt_6m` | Hoover | 近 6 月有需求月数 | 1 |
| `evt_cnt_12m` | Hoover | 近 12 月有需求月数 | 1 |
| `cumul_12m` | Hoover | 近 12 月累计需求量 | 1 |
| `month_freq` | Occurrence | 该月在训练集的平均需求概率 | 1 |
| **合计** | | | **5** |

加上原有的 4 外部因子 + 6 lag/rolling + 4 sin/cos = 18 维输入（基线 13 维）。

### 7.2 启用/取消方式

```python
# main.py 顶部
USE_EVENT_FEATURES = True   # 启用 EVT
USE_EVENT_FEATURES = False  # 取消 EVT, 回退到13维特征
```

### 7.3 实验效果

| 物资 | CV | 基线 R² | EVT R² | 改善 |
|------|:---:|:---:|:---:|:---:|
| 电容式电压互感器 | 0.66 | 0.325 | 0.634 | **+95%** |
| 交流支柱绝缘子 | 0.78 | 0.333 | 0.523 | **+57%** |
| 断路器保护 | 1.26 | 0.697 | 0.727 | +4% |
| 电抗器保护 | 0.92 | 0.019 | 0.039 | +105% |

## 八、总结

EVT 不改变模型，只改变"给模型看什么"。它的核心操作是：不把 ECP 数据描述成一条连续波形，而是描述成一系列离散事件（采购 → 等几个月 → 再采购 → 再等几个月）。

传统特征问"上个月多少"，EVT 特征问"上次是多久前、最近多频繁、这个月划算吗"。

对于事件规律性强的物资（每个月/季稳定采购），EVT 提供的信息和传统 lag 特征互补——这正是信息增益的来源。
