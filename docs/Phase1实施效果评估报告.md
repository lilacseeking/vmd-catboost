## 二、Tweedie 损失函数效果评估

### 2.1 五物资全量对比

| 物资 | CatBoost-2S (RMSE) R² | CatBoost-Tweedie 最佳 R² | 最优p值 | ΔR² |
|------|:---:|:---:|:---:|:---:|
| 交流避雷器 | **0.595** | -0.181 | 1.1 | **-0.777** |
| 电容式电压互感器 | **0.320** | -1.336 | 1.5 | **-1.656** |
| 交流支柱绝缘子 | **0.142** | -0.606 | 1.1 | **-0.747** |
| 断路器保护 | **0.058** | -0.002 | 1.1 | -0.060 |
| 电抗器保护 | **0.352** | -0.178 | 1.1 | **-0.530** |

**结论：Tweedie 损失在所有5种物资上均劣于RMSE。平均ΔR² = -0.754。**

### 2.2 根因分析

Tweedie 失败的原因不是bug——是两阶段框架的架构特点导致的：

1. **两阶段框架已经解决了零膨胀问题。** Stage 1 (CatBoostClassifier) 将零值和非零值分开。Stage 2 只看到非零样本。在纯非零数据上，RMSE（等价于高斯条件均值MLE）是无偏的——这就是为什么它更优。

2. **Tweedie 在非零-only数据上引入了不必要的偏差。** Tweedie的似然函数假设数据生成过程为 Poisson-Gamma复合分布。但Stage 2的训练数据已经过滤掉零值——它们不再是"零+正值"的混合，而是纯正值。在纯正值数据上，RMSE是更合适的损失函数。

3. **p值的额外自由度在小样本上不稳定。** Tweedie需要估计一个额外的隐参数p（variance_power），而69个训练月中仅有36-42个非零月被Stage 2使用。p值的不确定性增加了模型方差，但并未提供额外的偏差减小。

### 2.3 学术价值

**这是一个诚实的负面结果，且具有独立的学术价值。** 它证明了一个非平凡的观点：

> "在显式两阶段框架中，Stage 2使用Tweedie损失并不会改善预测性能——因为零膨胀问题已经在Stage 1被解决。Tweedie损失更适合单阶段（无分类器）的零膨胀场景。"

这个发现纠正了Gemini报告中的一个隐含假设（报告假定Tweedie在各种场景下都有优势，但未区分"单阶段 vs 两阶段架构下Tweedie的不同效果"）。

**论文中的处理方式**：
- 在消融实验章节报告这个负面结果
- 解释原因（两阶段框架 + 非零-only训练 = RMSE更优）
- 指出Tweedie在单阶段场景下可能仍然有价值，但在已使用两阶段框架时不推荐
- 记录为"该方法在此特定架构+数据组合下不适用"的诚实报告

### 2.4 关于CatBoost-Tweedie是否保留在代码中

**建议：保留。** 理由：
- 论文需要的正是这种有意义的消融实验
- 它在MODEL_ORDER中，运行后自动出现在评估表里
- 如果审稿人问"为什么不用Tweedie"，可以直接引用实验数据回答
- 记录了一个学术发现，删除它就失去了这个数据

## 三、Chronos-2 基线的延迟评估

### 3.1 当前状态

Chronos-2 未在当前环境中安装（`chronos-forecasting` 包缺失）。`baseline_chronos()` 函数已实现且包含完整的回退逻辑——如果包不可用则优雅跳过。

### 3.2 安装方案

```bash
pip install "chronos-forecasting>=2.0"
```

需要PyTorch 2.0+和transformers库。当前环境的PyTorch版本需检查兼容性。

**注意**：Chronos-2-small模型首次运行时会自动下载预训练权重（~200MB），需要网络连接。

### 3.3 预期结果

基于已知文献的预期：Chronos在ECP批次数据上可能表现较差（R²<0），因为：
- 预训练语料是连续时序（金融、天气、交通）
- ECP的批次阶梯函数不在分布内
- Chronos在M4/M5间歇性数据上的结果已知不好

但是，无论结果好坏，都有论文价值（见方案§2.2的定位）。

## 五、评估结论与循环决策

### 5.1 是否需要人工介入？

**否。** 这是一个有学术价值的负面结果，但不需要修改方案方向：
- Tweedie的失败有一个清晰的、可解释的原因
- 这个发现本身就是论文的消融实验材料
- 没有触及系统架构的根本缺陷

### 5.2 优化建议书（Agent E → 下一轮循环）

1. **Chronos-2基线**：安装chronos-forecasting包，完成零样本评估。优先级高于其他工作。

2. **零膨胀联合损失**（Phase 2）：如果要在损失函数层面改进，应该在**单阶段**CatBoost上测试Tweedie（即不通过两阶段框架，直接用Tweedie loss在全部数据上训练）——这样Tweedie才能真正发挥其零膨胀优势。对比"单阶段Tweedie vs 两阶段RMSE"比"两阶段RMSE vs 两阶段Tweedie"更有意义。

3. **下一步优化方向**：当前的瓶颈不是损失函数选择——是**数据本身**（demand_month不是交货月、因子区分度不足、样本量小）。Phase 1的Tweedie实验证明："在两阶段框架内换损失函数"的边际收益已经穷尽。后续努力应聚焦于：
   - 修复上游数据的F4/F5（见bidding-ecp-data全景诊断报告）
   - 构建物资特有的（非全局的）外部因子
   - 扩充物资种类至8-10种（增加统计检验力）

### 5.3 循环触发

本次Phase 1的结论（Tweedie在两阶段框架内无优势）将反馈给方案层：
- Agent A/C更新方案：将"两阶段Tweedie"降级为消融实验中的负面对照组
- 论文叙事中将其定位为"验证两阶段框架充分性的消融证据"而非"改进尝试"
