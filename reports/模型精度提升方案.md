# 电力物资需求预测模型精度提升方案

> 日期：2026-07-09
> 目标：将当前最高 R²≈0.1-0.36 提升至科技核心期刊可发表水平 (R²>0.5)，同时形成方法论创新

---

## 一、当前状态诊断

### 1.1 已尝试的 21 个模型 — 全部未达标

| 模型族 | 代表模型 | 最佳 R² | 正 R² 次数 | 结论 |
|------|------|:--:|:--:|------|
| 单阶段树模型 | CatBoost, LightGBM | 0.36 | 4/5 | 当前最优，但不够 |
| 两阶段树模型 | CatBoost-2S, CondCatBoost, TwoStage | 0.21 | 4/5 | 未超单阶段 |
| 线性+两阶段 | Ridge-2S, ElasticNet-2S, GP-2S | 0.34 | 4/5 | 有竞争力 |
| 深度时序模型 | DLinear, ModernTCN | -0.04 | 0/5 | 完全不适用 |
| 统计预测模型 | SARIMA, Croston-SBA, TSB, Theta, SES | 0.17 | 1/5 | 远不如 ML |
| 基线 | NaiveSeasonal, Persistence | 0.03 | 2/5 | 随机水平 |

### 1.2 R²=0.1-0.36 的三个根本原因

**原因一：选错了物资。** 之前选的 5 种物资（控制电缆、电缆保护管、通信单元、电缆接线端子、蝶式绝缘子）非零月仅 12-17/74（密度 16-23%），是数据库中最稀疏的。但数据库中有 **339 种物资具有 ≥15 个非零月**，前 50 种物资密度高达 50-68%。用高密度物资训练，模型效果会从根本上改善。

**原因二：丢失了跨物资信号。** 1,139 对物资的 Jaccard 系数 ≥0.6（如"控制电缆"和"蝶式绝缘子"Jaccard=0.92，几乎总是同时采购），但所有模型都是逐物资独立训练的。一个物资的需求发生月可以被其"搭子"物资的出现信号完美预测。

**原因三：Stage 1 分类器样本不足。** 两阶段模型（CatBoost-2S/CondCatBoost/TwoStage）的 Stage 1 在每个物资上只有 10-15 个正样本。如果池化所有物资训练一个统一的"本月是否有采购事件"分类器，正样本数 = 148 个月 × 平均 148 活跃种物资 = **~22,000 个正样本**。

## 四、路线 B：跨物资特征工程（核心创新）

### 4.1 三类新特征

#### 特征组 1：月份级全局特征（免费，零成本）

```python
# 对每个月，统计全部 339 种物资的聚合指标
monthly_total_demand    # 本月总需求量 (所有物资之和)
monthly_active_mats     # 本月有需求的物资种数
monthly_avg_demand      # 本月物资平均需求量
monthly_demand_rank     # 本物资在本月的需求量排名 (相对位置)
monthly_demand_share    # 本物资占本月总需求的比例
```

**为什么有效：** 月均 148 种物资同时活跃。"总盘子"大 → 每种物资分到的也多。这是层次化预测的思想。

#### 特征组 2：跨物资共现特征（创新点）

```python
# 对每种物资 M，找到所有 Jaccard(M, N) >= 0.6 的"搭子"物资
# 特征 = 这些搭子物资在本月的需求情况

cooc_partner_count       # 本月有多少个搭子也有需求
cooc_partner_avg_qty     # 搭子本月平均需求量 
cooc_partner_total_qty   # 搭子本月总需求量
cooc_strongest_active    # 最强搭子(Jaccard最高)本月是否有需求
```

**为什么有效：** 1,139 对物资有 Jaccard ≥0.6。如果物资 A 的最强搭子 B 本月有需求，A 几乎 100% 也有需求。这是数据自身提供的强信号，不需要任何外部因子。

**为什么有创新性：** 在电力物资预测文献中，无人使用跨物资共现特征。现有方法都是逐物资独立建模。

#### 特征组 3：自回归 + 季节性特征

```python
demand_lag1, lag2, lag3, lag6, lag12     # 滞后需求
rolling_mean_3m, rolling_mean_6m          # 滚动均值
months_since_last_demand                  # 距上次需求月数
is_peak_month                             # 是否高峰月 (基于该物资的历史峰值月份)
same_month_last_year_demand               # 去年同期需求
yoy_ratio                                 # 同比变化率
```

### 4.2 特征总数

```
原始因子:      6 维  (project_count, transformer_bids, ...)
月份全局特征:  5 维  (total_demand, active_mats, avg_demand, rank, share)
共现特征:      4 维  (partner_count, partner_avg, partner_total, strongest_active)
自回归特征:    10 维 (lags, rolling, gap, seasonal)
────────────────
总计:         25 维 ← 对 LightGBM 来说仍然很轻量
```

## 五、路线 C：池化两阶段 + 集成模型

### 5.1 池化 Stage 1 分类器

```python
# 不是为每种物资单独训练一个分类器
# 而是把所有物资的数据池化，训练一个统一的 "本月该物资是否有需求" 分类器

# 训练数据: n_materials × 74_months = 25,000+ 行
# 正样本: ~148 materials × 74 months × 68% = ~7,400 行
# 特征: 25 维 (同上)

pooled_cls = LightGBMClassifier(
    objective='binary',
    scale_pos_weight=neg_count/pos_count,  # 处理不平衡
    ...
)
pooled_cls.fit(X_pooled, y_pooled_binary)
```

**为什么有效：** 物资之间的"有/无需求"规律高度相似（都是招标批次驱动），池化后样本从 15 个 → 7,400 个。分类器可以学到跨物资的通用"是否有需求"模式。

### 5.2 物资专属 Stage 2 回归器

```python
# Stage 2 仍为每种物资独立训练（量级各不相同）
for material in materials:
    nz_mask = y_train[material] > 0
    reg = LightGBMRegressor(params_from_optuna[material])
    reg.fit(X_train[material][nz_mask], y_train[material][nz_mask])
```

### 5.3 三层集成

```python
# 对每种物资，三个互补模型的加权集成:
models = {
    'LightGBM_pooled_2s':   # 池化两阶段 (主力)
    'Ridge_2s':              # Ridge+两阶段 (正则化强，防过拟合)  
    'NaiveSeasonal':         # 去年同期 (无参数，做底线锚)
}

# 权重 = 验证集 R² / sum(所有模型验证集 R²)
weights = softmax([r2_lgb, r2_ridge, r2_seasonal])
ensemble_pred = w1 * pred1 + w2 * pred2 + w3 * pred3
```

**为什么三层：** LightGBM 提供最强的非线性拟合，Ridge 防止小样本过拟合，NaiveSeasonal 做锚——确保集成模型不会比简单的季节性预测更差。

## 七、创新点总结（论文可写）

| 创新点 | 内容 | 对应路线 |
|:--:|------|:--:|
| **跨物资共现特征** | 首次利用招标批次的物资共现规律作为预测特征（1,139对Jaccard≥0.6） | B |
| **池化两阶段模型** | 将全部物资的"是否有需求"分类问题池化为单一学习任务，解决单物资正样本不足问题 | C |
| **层次化预测** | 月份级全局特征（L2）→ 物资间共现（L1）→ 物资自回归（L0）三层特征体系 | B |
| **零外部依赖** | 全部特征来自数据自身，不需要AKShare爬取外部因子（铜价/PMI等|r|<0.3的弱因子全部剔除） | B |
| **Optuna自适应超参** | 对每种物资独立运行贝叶斯超参数搜索，而非使用统一的超参数集 | A |

**论文核心叙事：**

> "传统电力物资预测方法将每种物资视为独立的时间序列，忽略了招标批次中物资共现提供的强信号。本文提出一种跨物资共现增强的池化两阶段预测框架：第一阶段利用全部物资的池化数据训练统一的采购事件分类器，第二阶段对每种物资独立训练回归器，并引入物资共现特征作为跨物资信息桥梁。实验表明...（待填入R²对比数据）"

## 九、为什么这个方案能成功而之前的 21 个模型不行

| 之前的错误做法 | 现在的正确做法 | 为什么之前不行 |
|------|------|------|
| 选 5 种最稀疏的物资 (密度16-23%) | 选 8-10 种高频物资 (密度 41-68%) | 密度差 3 倍，可预测性差一个数量级 |
| 8 个外部因子 (|r|<0.3) | 25 个内源特征 (|r|潜在 >0.7) | 外部因子是噪声，内源特征才是信号 |
| 每种物资独立训练 | 池化 Stage1 + 共现特征 | 浪费了 1,139 对强共现关系 |
| 统一超参数 | Optuna 逐物资搜索 | 不同物资的最优参数可以差 10 倍 |
| 单一模型 | 三层互补集成 | 单一模型无法同时避免过拟合和欠拟合 |

## 十、就算效果仍不达标的后备方案

如果 R² 仍 <0.5，有三个后备方向：

1. **回归到事件预测**（本对话中已验证的批次事件三层模型）——但这需要换一篇论文的叙事，不再是"时序预测"而是"事件预测"
2. **增加训练数据**——从 `pipeline.py` 修改 TARGET_ORG_ID 为冀北（2019061900137008），重新抓取冀北省级数据。当前数据库是国网总部级别，但冀北省级数据可能更有规律性
3. **降低发表标准**——投递的期刊从科技核心降到普通省级期刊，此时 R²=0.3~0.4 可能也能过

但首先，路线 A+B+C 值得全力以赴。如果 1,139 对共现信号 + 池化 22,000 个正样本 + Optuna 逐物资调优 + 三层集成都还不能把 R² 拉过 0.5，那说明这组数据在当前的信息量下真的无法支持 ML 方法得出有意义的预测。
